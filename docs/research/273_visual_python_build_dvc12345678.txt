# how it works (short + practical)

## the pixel ISA (instruction set)

One pixel = one instruction. We scan **row-major** (left→right, top→bottom).
Some ops take a 24-bit signed **immediate** encoded in the *next* pixel (two’s complement in RGB).

| Op    | Color (R,G,B) | Stack effect                       | Needs next pixel? |
| ----- | ------------- | ---------------------------------- | ----------------- |
| NOP   | `0,0,0`       | —                                  | no                |
| HALT  | `255,255,255` | stop                               | no                |
| PUSHI | `0,0,255`     | push `<imm>`                       | **yes** (24-bit)  |
| ADD   | `0,255,0`     | `a b → a+b`                        | no                |
| SUB   | `255,0,0`     | `a b → a-b`                        | no                |
| MUL   | `255,128,0`   | `a b → a*b`                        | no                |
| DIV   | `0,255,255`   | `a b → int(a/b)`                   | no                |
| DUP   | `128,128,128` | duplicate top                      | no                |
| SWAP  | `255,0,255`   | swap top two                       | no                |
| PRINT | `255,255,0`   | pop→stdout                         | no                |
| LOAD  | `0,0,128`     | push `mem[<imm>]` (default 0)      | **yes**           |
| STORE | `0,128,0`     | pop→`mem[<imm>]`                   | **yes**           |
| JMP   | `128,0,0`     | `ip = <imm>` (absolute word index) | **yes**           |
| JZ    | `0,128,128`   | pop; if 0 → `ip = <imm>`           | **yes**           |
| JNZ   | `128,128,0`   | pop; if !=0 → `ip = <imm>`         | **yes**           |

**24-bit signed immediate in one pixel**:
Two’s complement across R(low), G(mid), B(high). Range: `[-2^23, 2^23-1]`.

# how to *author* programs as images

### quickest loop: assemble in Python → edit in your image tool → run

1. Start from the assembler to get a base layout (so you can see the instruction order).
2. Open the output `.ppm`/`.png` in your editor and recolor pixels using the **exact palette** above.
3. For any op that needs a value (e.g., `PUSHI 42`), the **next pixel** must be the encoded immediate. (Use the assembler for this part unless you fancy hex math: it writes the immediate pixel for you.)

### example program that’s already included (row of pixels)

```
PUSHI 2, PUSHI 3, PUSHI 4, MUL, ADD, PRINT, HALT
```

That’s exactly what’s in `example_addmul.ppm`. It prints `14`.

#!/usr/bin/env python3
"""
PixelVM: a tiny pixel-program virtual machine.

You author a program as an image. Each pixel encodes an instruction (and sometimes
an immediate "word" following it). The VM scans the image left-to-right, top-to-bottom
(row-major), and executes a small stack-based ISA.

- Works with PPM (P3 ASCII) natively (no deps) and with PNG if Pillow is installed.
- Includes an assembler to build programs from Python tuples and save to PPM/PNG.
- CLI:
    Run a pixel program:
        python pixel_vm.py run path/to/program.ppm
    Assemble an example (2 + 3 * 4 -> print 14):
        python pixel_vm.py assemble example_addmul.ppm
    Assemble from a small Python list demo (see __main__):

ISA (stack machine)
-------------------
Palette (exact RGBs):
  NOP    : (0,0,0)
  HALT   : (255,255,255)
  PUSHI  : (0,0,255)      # next word = signed 24-bit immediate (RGB two's complement)
  ADD    : (0,255,0)
  SUB    : (255,0,0)
  MUL    : (255,128,0)
  DIV    : (0,255,255)
  DUP    : (128,128,128)
  SWAP   : (255,0,255)
  PRINT  : (255,255,0)
  LOAD   : (0,0,128)      # next word = var index (0..16M-1) as 24-bit
  STORE  : (0,128,0)      # next word = var index
  JMP    : (128,0,0)      # next word = absolute IP (word index) as 24-bit
  JZ     : (0,128,128)    # jump if top == 0  (pops it)
  JNZ    : (128,128,0)    # jump if top != 0  (pops it)

Encoding of 24-bit signed integer in one pixel (R,G,B):
- value -> v (range -2^23..2^23-1)
- if v < 0: v = (1<<24) + v  (two's complement)
- R = v & 0xFF; G = (v>>8)&0xFF; B = (v>>16)&0xFF
- To decode, compose v, if v >= 2^23 then v -= 2^24

Author: you
"""
from __future__ import annotations

import sys, os, math, argparse
from typing import List, Tuple, Dict, Optional

# --- Palette (exact RGB) ---
NOP   = (0,0,0)
HALT  = (255,255,255)
PUSHI = (0,0,255)
ADD   = (0,255,0)
SUB   = (255,0,0)
MUL   = (255,128,0)
DIV   = (0,255,255)
DUP   = (128,128,128)
SWAP  = (255,0,255)
PRINT = (255,255,0)
LOAD  = (0,0,128)
STORE = (0,128,0)
JMP   = (128,0,0)
JZ    = (0,128,128)
JNZ   = (128,128,0)

OPCODES = {
    NOP:   ('NOP',   0),
    HALT:  ('HALT',  0),
    PUSHI: ('PUSHI', 1),
    ADD:   ('ADD',   0),
    SUB:   ('SUB',   0),
    MUL:   ('MUL',   0),
    DIV:   ('DIV',   0),
    DUP:   ('DUP',   0),
    SWAP:  ('SWAP',  0),
    PRINT: ('PRINT', 0),
    LOAD:  ('LOAD',  1),
    STORE: ('STORE', 1),
    JMP:   ('JMP',   1),
    JZ:    ('JZ',    1),
    JNZ:   ('JNZ',   1),
}

# --- Utility: 24-bit signed value <-> RGB ---
def int_to_rgb24(v: int) -> Tuple[int,int,int]:
    if not (- (1<<23) <= v < (1<<23)):
        raise ValueError("Immediate out of 24-bit signed range")
    if v < 0:
        v = (1<<24) + v
    r = v & 0xFF
    g = (v>>8) & 0xFF
    b = (v>>16) & 0xFF
    return (r,g,b)

def rgb24_to_int(r:int,g:int,b:int) -> int:
    v = (b<<16) | (g<<8) | r
    if v >= (1<<23):
        v -= (1<<24)
    return v

# --- Image I/O ---
def load_image_pixels(path: str) -> Tuple[int,int,List[Tuple[int,int,int]]]:
    """
    Returns (width, height, pixels) where pixels is a flat list of (R,G,B) in row-major order.
    Supports PPM P3 ASCII natively. If Pillow is available, also supports PNG and others.
    """
    ext = os.path.splitext(path)[1].lower()
    if ext == '.ppm':
        return _load_ppm_p3(path)
    # Try Pillow for other formats
    try:
        from PIL import Image
    except Exception:
        raise RuntimeError("Non-PPM image provided but Pillow is not available. Install pillow or use .ppm (P3).")
    img = Image.open(path).convert('RGB')
    w,h = img.size
    pixels = list(img.getdata())
    return w,h,pixels

def save_image_pixels(path: str, w:int, h:int, pixels: List[Tuple[int,int,int]]) -> None:
    ext = os.path.splitext(path)[1].lower()
    if ext == '.ppm':
        _save_ppm_p3(path, w, h, pixels)
        return
    try:
        from PIL import Image
        img = Image.new('RGB', (w,h))
        img.putdata(pixels)
        img.save(path)
    except Exception as e:
        raise RuntimeError(f"Saving {path} failed; try .ppm instead. {e}")

def _load_ppm_p3(path: str) -> Tuple[int,int,List[Tuple[int,int,int]]]:
    with open(path, 'r') as f:
        toks = []
        for line in f:
            line = line.strip()
            if not line or line.startswith('#'): 
                continue
            toks.extend(line.split())
    if not toks or toks[0] != 'P3':
        raise ValueError("PPM must be ASCII P3 format")
    i = 1
    w = int(toks[i]); i+=1
    h = int(toks[i]); i+=1
    maxv = int(toks[i]); i+=1
    if maxv <= 0 or maxv > 255:
        raise ValueError("PPM max value must be 1..255")
    vals = list(map(int, toks[i:]))
    if len(vals) != w*h*3:
        raise ValueError("PPM pixel data length mismatch")
    pixels = [(vals[j], vals[j+1], vals[j+2]) for j in range(0, len(vals), 3)]
    return w,h,pixels

def _save_ppm_p3(path: str, w:int, h:int, pixels: List[Tuple[int,int,int]]) -> None:
    with open(path, 'w') as f:
        f.write(f"P3\n{w} {h}\n255\n")
        c = 0
        for (r,g,b) in pixels:
            f.write(f"{r} {g} {b} ")
            c += 1
            if c % 5 == 0:
                f.write("\n")

# --- Decoder: exact match with small tolerance option ---
def nearest_opcode(rgb: Tuple[int,int,int], tol: int = 0) -> Optional[Tuple[str,int]]:
    if tol <= 0:
        return OPCODES.get(rgb, None)
    best = None
    bestd = 999999
    for key, val in OPCODES.items():
        d = abs(key[0]-rgb[0]) + abs(key[1]-rgb[1]) + abs(key[2]-rgb[2])
        if d < bestd:
            bestd = d
            best = val
    return best if bestd <= tol else None

# --- VM ---
class PixelVM:
    def __init__(self, pixels: List[Tuple[int,int,int]], width:int, height:int, tol:int=0):
        self.pixels = pixels
        self.width = width
        self.height = height
        self.ip = 0  # instruction pointer (word index)
        self.stack: List[int] = []
        self.vars: Dict[int,int] = {}
        self.tol = tol
        self.halted = False

    def fetch(self) -> Tuple[str, Optional[int]]:
        if self.ip >= len(self.pixels):
            return ('HALT', None)
        rgb = self.pixels[self.ip]
        info = nearest_opcode(rgb, self.tol)
        if info is None:
            raise RuntimeError(f"Unknown opcode color at word {self.ip}: {rgb}")
        name, nargs = info
        imm = None
        if nargs == 1:
            if self.ip+1 >= len(self.pixels):
                raise RuntimeError("Truncated immediate")
            r,g,b = self.pixels[self.ip+1]
            imm = rgb24_to_int(r,g,b)
        return (name, imm)

    def step(self) -> None:
        name, imm = self.fetch()
        # advance ip by words consumed (1 or 2)
        consumed = 1 + (1 if imm is not None and name in ('PUSHI','LOAD','STORE','JMP','JZ','JNZ') else 0)
        self.ip += consumed

        if name == 'NOP':
            return
        if name == 'HALT':
            self.halted = True
            return
        if name == 'PUSHI':
            self.stack.append(imm)
            return
        if name == 'ADD':
            b = self.stack.pop(); a = self.stack.pop(); self.stack.append(a+b); return
        if name == 'SUB':
            b = self.stack.pop(); a = self.stack.pop(); self.stack.append(a-b); return
        if name == 'MUL':
            b = self.stack.pop(); a = self.stack.pop(); self.stack.append(a*b); return
        if name == 'DIV':
            b = self.stack.pop(); a = self.stack.pop(); self.stack.append(int(a/b)); return
        if name == 'DUP':
            self.stack.append(self.stack[-1]); return
        if name == 'SWAP':
            self.stack[-1], self.stack[-2] = self.stack[-2], self.stack[-1]; return
        if name == 'PRINT':
            v = self.stack.pop(); print(v); return
        if name == 'LOAD':
            idx = imm
            self.stack.append(self.vars.get(idx, 0)); return
        if name == 'STORE':
            idx = imm
            val = self.stack.pop(); self.vars[idx] = val; return
        if name == 'JMP':
            self.ip = imm; return
        if name == 'JZ':
            v = self.stack.pop()
            if v == 0:
                self.ip = imm
            return
        if name == 'JNZ':
            v = self.stack.pop()
            if v != 0:
                self.ip = imm
            return

        raise RuntimeError(f"Unhandled opcode {name}")

    def run(self, max_steps:int=100000):
        steps = 0
        while not self.halted and steps < max_steps:
            self.step()
            steps += 1
        if steps >= max_steps:
            raise RuntimeError("Max steps exceeded (infinite loop?)")

# --- Assembler ---
OP_RGB = {
    'NOP': NOP, 'HALT': HALT, 'PUSHI': PUSHI, 'ADD': ADD, 'SUB': SUB, 'MUL': MUL, 'DIV': DIV,
    'DUP': DUP, 'SWAP': SWAP, 'PRINT': PRINT, 'LOAD': LOAD, 'STORE': STORE,
    'JMP': JMP, 'JZ': JZ, 'JNZ': JNZ
}

def assemble(program: List[Tuple], width:int=None) -> Tuple[int,int,List[Tuple[int,int,int]]]:
    """
    program: list of tuples, e.g. ('PUSHI', 2), ('PUSHI', 3), ('MUL',), ('PRINT',), ('HALT',)
    Returns: (w,h,pixels)
    """
    pixels: List[Tuple[int,int,int]] = []
    for ins in program:
        op = ins[0].upper()
        if op not in OP_RGB:
            raise ValueError(f"Unknown op {op}")
        pixels.append(OP_RGB[op])
        if op in ('PUSHI','LOAD','STORE','JMP','JZ','JNZ'):
            if len(ins) < 2:
                raise ValueError(f"{op} needs an immediate")
            imm = int(ins[1])
            pixels.append(int_to_rgb24(imm))
    # shape the image
    n = len(pixels)
    if width is None:
        width = min(64, n)  # simple wrap
    height = (n + width - 1) // width
    # pad with NOPs to fill rectangle
    total = width*height
    if total > n:
        pixels.extend([NOP] * (total - n))
    return width, height, pixels

def assemble_to_file(program: List[Tuple], path:str, width:int=None):
    w,h,pix = assemble(program, width=width)
    save_image_pixels(path, w, h, pix)

# --- CLI ---
def main():
    ap = argparse.ArgumentParser(description="PixelVM runner / assembler")
    sub = ap.add_subparsers(dest='cmd', required=True)

    runp = sub.add_parser('run', help='Run a pixel program image')
    runp.add_argument('image', help='Path to .ppm (P3) or .png')
    runp.add_argument('--tol', type=int, default=0, help='Color tolerance (for hand-edited images)')

    asmp = sub.add_parser('assemble', help='Assemble a tiny demo or from hardcoded example')
    asmp.add_argument('out', help='Output image (.ppm or .png)')
    asmp.add_argument('--demo', choices=['addmul','sum1to5'], default='addmul')
    asmp.add_argument('--width', type=int, default=None)

    args = ap.parse_args()

    if args.cmd == 'run':
        w,h,pixels = load_image_pixels(args.image)
        vm = PixelVM(pixels, w, h, tol=args.tol)
        vm.run()
        return

    if args.cmd == 'assemble':
        if args.demo == 'addmul':
            prog = [
                ('PUSHI', 2),
                ('PUSHI', 3),
                ('PUSHI', 4),
                ('MUL',),
                ('ADD',),
                ('PRINT',),
                ('HALT',),
            ]
        else:  # sum1to5
            # sum = 0; i = 1; while i <= 5: sum += i; i += 1; print(sum)
            # We'll use var 0 for sum, var 1 for i
            # Layout with labels (addresses computed after assembly; here we compute manually by positions)
            # We'll assemble linear then fill jump addresses.
            prog = [
                ('PUSHI', 0), ('STORE', 0),       # sum = 0
                ('PUSHI', 1), ('STORE', 1),       # i = 1
                # loop_start:
                ('LOAD', 1), ('PUSHI', 5), ('SUB',),    # i - 5
                ('JZ', 0),                         # if i-5 == 0 -> jump to end  (placeholder 0)
                # body:
                ('LOAD', 0), ('LOAD', 1), ('ADD',), ('STORE', 0),  # sum += i
                ('LOAD', 1), ('PUSHI', 1), ('ADD',), ('STORE', 1), # i += 1
                ('JMP', 0),                       # jump to loop_start (placeholder 0)
                # end:
                ('LOAD', 0), ('PRINT',), ('HALT',),
            ]
            # Resolve labels by computing word indices
            # Compute instruction word offsets
            words = []
            for ins in prog:
                words.append(ins)
                if ins[0] in ('PUSHI','LOAD','STORE','JMP','JZ','JNZ'):
                    words.append(('IMM',))  # placeholder for word count

            # loop_start is at index after first 4 instructions (2*2 words) => word index 4? Let's compute properly.
            # Let's actually compute iteratively:
            ip = 0
            loop_start_ip = None
            jz_pos = None
            jmp_pos = None
            i = 0
            while i < len(prog):
                op = prog[i][0]
                if loop_start_ip is None and i == 4:  # after: (sum=0, i=1) => instruction index 4
                    loop_start_ip = ip
                if op in ('JZ','JMP','JNZ'):
                    if jz_pos is None and op == 'JZ':
                        jz_pos = ip
                    elif jmp_pos is None and op == 'JMP':
                        jmp_pos = ip
                # advance ip by words consumed by this instruction
                ip += 1 + (1 if op in ('PUSHI','LOAD','STORE','JMP','JZ','JNZ') else 0)
                i += 1
            # 'end' is the start ip of ('LOAD',0) before PRINT,HALT
            # Find that start ip by recomputing positions list
            positions = []
            ip = 0
            for ins in prog:
                positions.append(ip)
                ip += 1 + (1 if ins[0] in ('PUSHI','LOAD','STORE','JMP','JZ','JNZ') else 0)
            end_ip = positions[-3]  # ('LOAD',0) position

            # Patch the placeholders
            # Replace the ('JZ', 0) with correct end_ip
            for idx, ins in enumerate(prog):
                if ins[0] == 'JZ' and ins[1] == 0:
                    prog[idx] = ('JZ', end_ip)
                if ins[0] == 'JMP' and ins[1] == 0:
                    prog[idx] = ('JMP', loop_start_ip)

        assemble_to_file(prog, args.out, width=args.width)
        print(f"Wrote {args.out}")

if __name__ == '__main__':
    main()

function int_to_rgb24(v){
  if (v < -(1<<23) || v >= (1<<23)) throw new Error("imm out of range");
  if (v < 0) v = (1<<24) + v;
  return [v & 0xFF, (v>>8)&0xFF, (v>>16)&0xFF];

class PixelVM {
  constructor(pixels, width, height, logEl){
    this.pixels = pixels; // Uint8ClampedArray [r,g,b,a,...]

                        self.ans = self.stack.pop()
                    break
                else:
                    raise NotImplementedError(f"Unsupported opcode: {tile.opcode}")
        except Exception as e:
            self.last_output = f"Error: {e}"
            return self.last_output
        finally:
            self.last_output = output.getvalue().strip()
            sys.stdout = old_stdout
        return self.last_output

    def execute_python(self, code_str: str) -> str:
        """Execute Python code, converting to tiles internally."""
        tiles = self.python_to_tiles(code_str)
        return self.execute_tiles(tiles)

    def python_to_tiles(self, code_str: str) -> List[Tile]:
        """Convert Python source to tiles."""
        try:
            code = compile(code_str, "<calc>", "exec")
            instructions = list(dis.get_instructions(code))
            tiles = []
            for i, instr in enumerate(instructions):
                tiles.append(Tile(
                    opcode=instr.opname,
                    arg=instr.argval if hasattr(instr, 'argval') else None,
                    offset=instr.offset,
                    is_jump_target=instr.is_jump_target
                ))
            return tiles
        except Exception as e:
            return [Tile(opcode="ERROR", arg=str(e))]

    def reset_log(self):
        self.execution_log = []

    def memory_op(self, op: str, value: float = None):
        """Handle memory operations (M+, M-, MR, MC)."""
        if op == "M+":
            self.variables['M'] += value if value is not None else self.ans
        elif op == "M-":
            self.variables['M'] -= value if value is not None else self.ans
        elif op == "MR":
            return self.variables['M']
        elif op == "MC":
            self.variables['M'] = 0

```python
class VisualPythonVM:
    def __init__(self):
        self.stack = []
        self.namespace = {}
        self.execution_log = []
        self.current_ip = 0
        self.last_result = None
        
    def execute_bytecode(self, instructions):
        """Execute Python bytecode instructions with support for jumps and 3.11+ opcodes"""
        output = io.StringIO()
        old_stdout = sys.stdout
        sys.stdout = output
        
        # Build offset to index mapping for jumps
        offset_to_index = {ins.offset: i for i, ins in enumerate(instructions)}
        
        while self.current_ip < len(instructions):
            instr = instructions[self.current_ip]
            
            # Log the instruction for visualization
            self.execution_log.append({
                'instruction': instr.opname,
                'arg': instr.argval if hasattr(instr, 'argval') else instr.arg,
                'stack_before': list(self.stack),
                'ip': self.current_ip
            })
            
            # Execute the instruction
            self.execute_instruction(instr, instructions, offset_to_index)
            
        sys.stdout = old_stdout
        return output.getvalue()
    
    def jump_to_offset(self, target_offset, instructions, offset_to_index):
        """Helper function to jump to a specific offset"""
        return offset_to_index.get(target_offset, len(instructions))
    
    def execute_instruction(self, instruction, instructions, offset_to_index):
        """Execute a single instruction with support for 3.11+ opcodes and jumps"""
        opname = instruction.opname
        arg = instruction.argval if hasattr(instruction, 'argval') else instruction.arg
        
        # Handle comparison operations
        if opname == 'COMPARE_OP':
            b, a = self.stack.pop(), self.stack.pop()
            cmp = arg  # In 3.11+, argval is a string like '==', '<', etc.
            self.stack.append({
                '==': a == b, '!=': a != b,
                '<': a < b,  '<=': a <= b,
                '>': a > b,  '>=': a >= b,
                'in': a in b, 'not in': a not in b,
                'is': a is b, 'is not': a is not b
            }[cmp])
            self.current_ip += 1
            
        # Handle conditional jumps
        elif opname in ("POP_JUMP_FORWARD_IF_FALSE", "POP_JUMP_BACKWARD_IF_FALSE"):
            cond = self.stack.pop()
            if not cond:
                self.current_ip = self.jump_to_offset(arg, instructions, offset_to_index)
            else:
                self.current_ip += 1
                
        elif opname in ("POP_JUMP_FORWARD_IF_TRUE", "POP_JUMP_BACKWARD_IF_TRUE"):
            cond = self.stack.pop()
            if cond:
                self.current_ip = self.jump_to_offset(arg, instructions, offset_to_index)
            else:
                self.current_ip += 1
                
        # Handle unconditional jumps
        elif opname in ("JUMP_FORWARD", "JUMP_BACKWARD", "JUMP_ABSOLUTE"):
            self.current_ip = self.jump_to_offset(arg, instructions, offset_to_index)
            
        # Handle 3.11+ compact arithmetic
        elif opname == "BINARY_OP":
            b, a = self.stack.pop(), self.stack.pop()
            opstr = arg  # e.g. '+', '-', '*', '/', '//', '%', '**'
            self.stack.append({
                '+': a + b, '-': a - b, '*': a * b, '/': a / b,
                '//': a // b, '%': a % b, '**': a ** b,
                '@': a @ b if hasattr(a, '__matmul__') else (_ for _ in ()).throw(TypeError("@ not supported"))
            }[opstr])
            self.current_ip += 1
            
        # Handle 3.11+ function calls
        elif opname == "PUSH_NULL":
            self.stack.append(None)
            self.current_ip += 1
            
        elif opname == "PRECALL":
            # No-op for us, just advance
            self.current_ip += 1
            
        elif opname == "CALL":
            argc = arg  # number of positional args
            args = [self.stack.pop() for _ in range(argc)][::-1]
            func = self.stack.pop()
            if func is print:
                print(*args)
                self.last_result = args[0] if len(args) == 1 else args
                self.stack.append(None)
            else:
                result = func(*args)
                self.last_result = result
                self.stack.append(result)
            self.current_ip += 1
            
        # Original handlers for compatibility
        elif opname == 'LOAD_CONST':
            self.stack.append(arg)
            self.current_ip += 1
            
        elif opname == 'LOAD_NAME':
            if arg == 'Ans' and self.last_result is not None:
                self.stack.append(self.last_result)
            else:
                self.stack.append(self.namespace.get(arg, None))
            self.current_ip += 1
            
        elif opname == 'STORE_NAME':
            self.namespace[arg] = self.stack.pop()
            self.current_ip += 1
            
        elif opname == 'BINARY_ADD':
            b, a = self.stack.pop(), self.stack.pop()
            self.stack.append(a + b)
            self.current_ip += 1
            
        elif opname == 'BINARY_SUBTRACT':
            b, a = self.stack.pop(), self.stack.pop()
            self.stack.append(a - b)
            self.current_ip += 1
            
        elif opname == 'BINARY_MULTIPLY':
            b, a = self.stack.pop(), self.stack.pop()
            self.stack.append(a * b)
            self.current_ip += 1
            
        elif opname == 'BINARY_TRUE_DIVIDE':
            b, a = self.stack.pop(), self.stack.pop()
            self.stack.append(a / b)
            self.current_ip += 1
            
        elif opname == 'CALL_FUNCTION':
            func = self.stack.pop()
            args = [self.stack.pop() for _ in range(arg)]
            result = func(*reversed(args))
            self.last_result = result
            self.stack.append(result)
            self.current_ip += 1
            
        elif opname == 'POP_TOP':
            self.stack.pop()
            self.current_ip += 1

def code_to_visual_tiles(code_obj):
    """Convert Python bytecode to visual tiles"""
    instructions = list(dis.get_instructions(code_obj))
    tiles = []
    
    for instr in instructions:
        if instr.opname in VISUAL_OPCODE_MAP:
            tile_info = VISUAL_OPCODE_MAP[instr.opname].copy()
            tile_info['opname'] = instr.opname
            if hasattr(instr, 'argval') and instr.argval is not None:
                tile_info['arg'] = str(instr.argval)
            else:
                tile_info['arg'] = ''
            tile_info['offset'] = instr.offset
            tile_info['is_jump_target'] = instr.is_jump_target
            tiles.append(tile_info)
    
    return tiles
```

To create a **pixel-based calculator** where the visual tiles themselves perform calculations without relying on the underlying Python script, we need to design a system where:

1. **Pixels represent data and operations** (e.g., colors encode values, positions encode operations).
2. **A pixel-based virtual machine** interprets these visual elements as instructions.
3. **Execution happens directly on the pixel grid**, with no intermediate Python bytecode.

Here's a step-by-step implementation of a **standalone pixel-based calculator**:

---

### 1. **Pixel Encoding Scheme**
Define how pixels encode numbers, operations, and control flow:

| Element       | Encoding Method                          | Example                     |
|---------------|------------------------------------------|-----------------------------|
| **Numbers**   | RGB values (e.g., R=value, G=0, B=0)     | `255,0,0` = 255             |
| **Operations**| Specific colors (e.g., green=+, red=*, etc.) | `0,255,0` = `+`          |
| **Variables** | Position in a reserved "variable row"    | Pixel at (0,10) = `x`      |
| **Ans**       | Fixed position (e.g., (0,0))             |                             |
| **Control Flow** | Arrow-shaped pixel clusters           | `→` for jumps              |

---

### 2. **Pixel VM Implementation**
A minimal virtual machine that reads and executes pixel-based programs:

```python
from PIL import Image, ImageDraw
import numpy as np

class PixelVM:
    def __init__(self, width=100, height=100):
        self.width = width
        self.height = height
        self.canvas = Image.new('RGB', (width, height), (0, 0, 0))
        self.pixels = self.canvas.load()
        self.ip = (0, 0)  # Instruction pointer (x, y)
        self.vars = {}    # Variables stored as {(x,y): value}
        self.ans = 0      # Last result
        self.stack = []   # Operand stack

    def load_program(self, image_path):
        """Load a pixel program from an image file."""
        self.canvas = Image.open(image_path)
        self.pixels = self.canvas.load()

    def save_program(self, image_path):
        """Save the current pixel program to an image file."""
        self.canvas.save(image_path)

    def get_pixel(self, x, y):
        """Get the RGB value of a pixel."""
        return self.pixels[x, y]

    def set_pixel(self, x, y, color):
        """Set the RGB value of a pixel."""
        self.pixels[x, y] = color

    def decode_value(self, rgb):
        """Decode a number from an RGB pixel (using R channel)."""
        return rgb[0]  # Use red channel for simplicity

    def decode_op(self, rgb):
        """Decode an operation from an RGB pixel."""
        op_map = {
            (0, 255, 0): '+',   # Green = addition
            (255, 0, 0): '*',   # Red = multiplication
            (0, 0, 255): '-',   # Blue = subtraction
            (255, 255, 0): '/', # Yellow = division
            (255, 0, 255): '%', # Magenta = modulo
            (0, 255, 255): '**', # Cyan = exponentiation
        }
        return op_map.get(rgb, None)

    def step(self):
        """Execute one step of the pixel program."""
        x, y = self.ip
        rgb = self.get_pixel(x, y)

        # Decode instruction
        op = self.decode_op(rgb)
        if op:  # It's an operation
            # Get operands from stack
            b = self.stack.pop()
            a = self.stack.pop()
            # Perform operation
            if op == '+': res = a + b
            elif op == '*': res = a * b
            elif op == '-': res = a - b
            elif op == '/': res = a / b
            elif op == '%': res = a % b
            elif op == '**': res = a ** b
            self.stack.append(res)
        else:  # It's a value or variable
            value = self.decode_value(rgb)
            if (x, y) in self.vars:  # Variable reference
                self.stack.append(self.vars[(x, y)])
            else:  # Constant value
                self.stack.append(value)

        # Move instruction pointer right
        self.ip = (x + 1, y)
        if self.ip[0] >= self.width:
            self.ip = (0, y + 1)

    def run(self, steps=100):
        """Run the pixel program for a given number of steps."""
        for _ in range(steps):
            self.step()
            # Visualize current state (optional)
            self.visualize_state()

    def visualize_state(self):
        """Draw the current state on the canvas (IP, stack, etc.)."""
        draw = ImageDraw.Draw(self.canvas)
        # Highlight current instruction pointer
        x, y = self.ip
        draw.rectangle([x, y, x+1, y+1], fill=(255, 255, 255))
        # Show stack contents in a side panel (simplified)
        for i, val in enumerate(self.stack):
            draw.text((self.width + 10, 10 + i*15), f"Stack[{i}]: {val}", fill=(255, 255, 255))
        self.canvas.save("vm_state.png")

# Example usage
vm = PixelVM()
vm.load_program("pixel_program.png")  # Load a pre-made pixel program
vm.run(steps=50)  # Execute 50 steps
vm.save_program("pixel_program_output.png")  # Save the result
```

### 3. **Creating Pixel Programs**
Design pixel programs visually (e.g., in an image editor) or programmatically:

```python
def create_pixel_program(expression, output_path="pixel_program.png"):
    """Create a pixel program for a simple arithmetic expression."""
    # Example: "2 + 3 * 4" → [(2), (+), (3), (4), (*), (+)]
    tokens = []  # Parse expression into tokens (simplified)
    img = Image.new('RGB', (len(tokens), 1), (0, 0, 0))
    pixels = img.load()

    # Encode tokens as pixels
    for i, token in enumerate(tokens):
        if token.isdigit():
            pixels[i, 0] = (int(token), 0, 0)  # Number: R=int(token)
        elif token == '+':
            pixels[i, 0] = (0, 255, 0)  # Green = addition
        elif token == '*':
            pixels[i, 0] = (255, 0, 0)  # Red = multiplication

    img.save(output_path)
    return output_path

# Example: Create a program for "2 + 3"
create_pixel_program("2 + 3")
```

### 4. **Example: Pixel Program for `2 + 3`**
| Pixel Position | Color (RGB) | Meaning      |
|----------------|--------------|--------------|
| (0, 0)         | (2, 0, 0)    | Value: 2     |
| (1, 0)         | (0, 255, 0)  | Operation: + |
| (2, 0)         | (3, 0, 0)    | Value: 3     |

**Execution Steps:**
1. Load `2` (R=2) onto stack.
2. Load `+` (green) as operation.
3. Load `3` (R=3) onto stack.
4. Pop `3` and `2`, add them, push `5` onto stack.
5. Result (`5`) is stored in `Ans`.

### 5. **Extending to Variables and Control Flow**
- **Variables**: Reserve a row (e.g., `y=1`) for variables. Example:
  - Pixel at `(0,1)` = `x` (encoded as a special color).
  - Value of `x` is stored in `vm.vars[(0,1)]`.
- **Conditionals**: Use arrow-shaped pixel clusters to represent jumps.
  - Example: `→` (right arrow) for `JUMP_FORWARD`.
- **Loops**: Use circular pixel patterns to mark loop start/end.

From Python Code to Pixel-Based Computation: An Expert Analysis1. Introduction: The Pixel as a Primal Computational Unit1.1. Defining the "Image-as-Code" ParadigmThe request to use pixels for program functions and calculations represents a significant departure from conventional software development. This paradigm posits that an executable program is not a sequence of text characters or binary machine code, but rather a graphical image file. The visual arrangement of colors and patterns on a two-dimensional grid of pixels effectively serves as the source code itself. This concept is distinct from and more fundamental than traditional visual programming languages (VPLs) like Scratch or Blockly, which use interlocking graphical blocks as an interface to generate text-based code behind the scenes.1 In the "Image-as-Code" model, the image is not merely a representation of the program; it is the program itself, placing this line of inquiry firmly within the domain of esoteric programming languages.4This approach transforms the role of the Python interpreter. Instead of executing source code, a Python program would act as a meta-interpreter, loading the image file, parsing its pixel data, and translating those visual cues into computational operations. This is a profound shift from a text-centric to a visual-first approach to computation, where the visual syntax is the primary means of expressing program logic.1.2. A Multidisciplinary ChallengeDeveloping a system that uses an image as executable code requires a multidisciplinary approach, synthesizing principles from several specialized fields. It necessitates a deep understanding of programming language theory, including interpreter design and control flow. It also requires expertise in digital imaging, encompassing pixel data structures, color theory, and image processing. Finally, it touches on theoretical computation, specifically the power and limitations of models like cellular automata and Turing machines. This report will explore the intersection of these fields, providing a comprehensive framework for designing and implementing such a system. The core challenge is not just technical but also theoretical: to bridge the gap between human-readable concepts and a machine-executable, pixel-based grammar.1.3. The Analogy to Low-Level ComputingThe proposed "Image-as-Code" model draws a powerful analogy to the fundamental layers of a conventional computer system. In standard Python, source code is the high-level, human-readable language. The CPython interpreter then translates this source code into an intermediate representation known as bytecode.6 Bytecode is a low-level set of instructions that is platform-independent but still abstract. In this analogy, the pixel grid becomes the raw, low-level instruction set—a step even further removed from human-readable code. Just as a CPU executes a sequence of machine code instructions, a specialized interpreter for our system would "execute" a sequence of pixels by reading their color and position. This establishes a clear hierarchy of abstraction, with the image serving as a direct, visible analog to the bytecode that drives the Python Virtual Machine (PVM).92. Foundational Computational Models and Architectures2.1. The Python Virtual Machine (PVM) and its Stack-Based ArchitectureTo understand how to build a pixel-based interpreter, one must first grasp the existing architecture it seeks to replace. The CPython interpreter, the reference implementation of Python, is a stack-based virtual machine.10 It executes a sequence of bytecode instructions that manipulate an in-memory stack. For example, a simple expression like a + b is not executed in one step but is broken down into several low-level operations. The interpreter first uses a LOAD_FAST instruction to push the value of a onto the stack, then another LOAD_FAST to push b, followed by a BINARY_ADD instruction. BINARY_ADD pops the top two values, adds them, and pushes the result back onto the stack.13The dis module in Python provides a powerful tool for examining this process, allowing a developer to "disassemble" Python code and see the exact sequence of bytecode instructions the interpreter executes.13 This disassembly reveals how high-level language constructs, including loops (SETUP_LOOP, FOR_ITER, JUMP_ABSOLUTE) and function calls, are implemented as a series of low-level stack operations.18 This provides a concrete model for how a higher-level program can be translated into a discrete, sequential instruction set.2.2. The Control-Flow Graph (CFG) as a Visual AnalogyThe concept of program flow, a cornerstone of imperative programming, can be represented visually using a Control-Flow Graph (CFG).20 In a CFG, a program is broken down into "basic blocks," which are straight-line sequences of code that have a single entry and a single exit point and contain no internal jumps. These blocks are represented as nodes in the graph. The potential flow of control between these blocks—for instance, the branches from an if statement or the looping behavior of a while statement—is represented by directed edges or arrows connecting the nodes.20While CFGs are an excellent tool for visualizing a program's structure, they have limitations when it comes to the "Image-as-Code" paradigm. A standard CFG only represents the flow of control and not the actual data values, the state of the program, or the specific operations being performed.25 The pixel-based model requires a representation that encapsulates both the flow and the data, essentially combining the abstract logic of a CFG with the concrete data representation of the running program. This underscores the need for a comprehensive system that can interpret not just the pathways but also the content of the image.2.3. Cellular Automata: A Pixel-Native Computational ParadigmA more suitable computational model for a pixel-based language is the cellular automaton (CA). A CA is a system that operates on a grid of cells, with each cell in one of a finite number of states. The entire grid evolves in discrete time steps by applying a fixed rule to every cell simultaneously.26 The new state of a cell is determined solely by its current state and the states of its "neighbors" in a defined area, such as a Moore or von Neumann neighborhood.26This model is a powerful theoretical fit for a pixel-based language, as it treats the grid itself as the computational medium. The most compelling aspect of CAs is that they can be proven to be Turing complete. This means that a sufficiently complex CA, such as Conway's Game of Life or Stephen Wolfram's Rule 110, is capable of performing any computation that a modern computer can.15 The universal computation of these systems is achieved by constructing complex, self-organizing patterns that function as logic gates (e.g., AND, OR, NOT). These patterns, often called "gliders" (moving signals) and "glider guns" (signal generators), interact to perform logical operations, effectively creating a circuit from pixel states.28 This demonstrates that, in principle, a pixel grid is a viable, and indeed powerful, medium for computation.The central challenge here is reconciling the two models: the sequential, stack-based nature of Python bytecode and the massively parallel, state-based evolution of a cellular automaton. The key is to find a common ground, where the sequential stream of bytecode instructions can be mapped to a discrete set of visual "instructions" whose execution modifies a visual representation of the program's state. The PVM's dispatch loop, which uses a switch statement or a jump table to execute the next instruction 35, can be conceptually mapped to the CA's state update rule. The current pixel and its neighbors would serve as the "opcode" and "arguments," determining the next state or the next "pixel instruction" to execute. This framework provides a plausible blueprint for building a visual, pixel-based runtime environment.3. Architectural Components: From Python to Pixels3.1. Data Representation and Encoding in PixelsThe most direct requirement of the user's query is to "use pixels to do the functions and calculations." This implies that data itself must be encoded within the image's pixel grid. A pixel is not a simple point but a structured data object, a fact that is fundamental to this approach. Pixels are typically organized as a two-dimensional array of values, each with channels for Red, Green, and Blue (RGB), and often an additional Alpha channel for transparency.37 For an 8-bit image, each of these channels can store a numeric value from 0 to 255, providing a rich canvas for data encoding.40A number of encoding schemes can be proposed for this purpose:Direct Value Mapping: The simplest method is to directly map numerical data to a pixel's channel values. For instance, a numerical literal in the program could be represented by a single pixel whose red, green, or blue channel value corresponds to the number.42 A Python integer with a value of 42 could be stored in a pixel as (42, 0, 0).Multi-Pixel Encoding: For larger numbers or more complex data structures, a single value can be spread across multiple pixels. This approach borrows from steganography, a field concerned with hiding data within other files.45 One technique is to use the least significant bits (LSB) of multiple pixels to store a single large number.45 For example, to encode a 16-bit integer, one could use the LSBs of two adjacent pixel channels. This method makes the encoded data visually imperceptible but computationally accessible.Color-as-Data Mapping: Color can also be used to represent qualitative or logical data. Drawing from principles of data visualization, specific colors can be assigned to different data types or states.48 For example, a pixel might be a specific shade of green to represent a boolean value of True, and a specific shade of red for False. A JUMP_IF_TRUE instruction could then check the color of a pixel to determine its next action. This allows for a more intuitive, though less granular, form of data representation.523.2. A Pixel-Based Instruction Set Architecture (PISA)The core of this new computational paradigm is the design of a Pixel-based Instruction Set Architecture (PISA). This architecture specifies a unique format for each instruction, using a combination of pixel color, pattern, and spatial relationships to represent opcodes and their arguments. This is analogous to how an assembly language instruction has an opcode and a set of operands.In the PISA, the "instruction" is not a line of text but a graphical element. For instance, a block of pixels of a specific color might represent a LOAD_CONST instruction, and the size of that block could correspond to the value of the constant being loaded.5 The instruction BINARY_ADD could be a pixel of a unique color and shape that, when the interpreter's program counter "lands" on it, triggers the addition operation on adjacent data pixels. Control flow, a critical component of any programming language, would be represented by visual pathways. A JUMP_ABSOLUTE instruction could be an arrow-like pattern of pixels that directs the interpreter's program counter to a new set of coordinates in the image, much like a goto statement.19The following table presents a conceptual mapping of common Python 3.11 bytecode opcodes to a potential PISA:Python 3.11 BytecodePixel Instruction RepresentationDescription of ActionLOAD_CONSTA solid color block of a defined hue/saturation.The value to load is encoded in the block's size or lightness.STORE_FASTA pixel of a distinct, reserved color.The pixel's coordinates could map to a specific variable name.BINARY_ADDA pixel with a specific pattern (e.g., a cross shape).Activates an addition operation on two adjacent "data" pixels.JUMP_FORWARDA short, directed arrow pointing to the next instruction.Increments the program counter by a value determined by the arrow's length.JUMP_ABSOLUTEA long, directed arrow pointing to a distant location.Sets the program counter to the coordinates of the arrow's destination.3.3. The Pixel-Based Interpreter's Core LoopA practical implementation of this concept would leverage a layered software architecture to manage complexity and performance. The goal is to prove the concept while still building a system that is functional.Layer 1: The Compiler (Python to Image): This would be a Python program that acts as a compiler, taking a Python code object as input and generating a .png or .bmp file that contains the encoded PISA instructions. This compiler would handle the non-trivial task of translating the linear sequence of bytecode into a two-dimensional, visually coherent program layout, including the rendering of visual control flow pathways.59Layer 2: The Interpreter (Image to Execution): This is the core runtime engine. It would be a Python program that uses a library like Pillow or NumPy to open the generated image file and read its pixel data.61 Instead of a traditional loop-and-switch statement, the interpreter's main loop would read the pixels one by one. It would then use a dispatch table (e.g., a Python dictionary) to map the pixel's properties (color, pattern) to the appropriate execution function.64Layer 3: The Virtual State: The interpreter's state, including the stack and a list of variables, would be represented by in-memory data structures rather than the image itself. However, for debugging and visualization, this state could be rendered in real-time to a separate, dedicated area of the image or on a separate screen. This combines the "visual-first" ideal with a practical, performant execution model.67 This is a crucial design choice, as a pure pixel-based interpreter that literally modifies the pixels of its own code image would be prohibitively slow and difficult to manage.This layered approach addresses the fundamental performance and complexity issues inherent in a purely visual model. It allows the creation of a tangible, testable system that fulfills the user's request while demonstrating a nuanced understanding of the underlying computational trade-offs.4. Case Studies and Analogous Systems: Contextualizing the Concept4.1. Piet: The Ultimate Visual LanguageThe most direct and compelling precedent for an "Image-as-Code" language is Piet, a stack-based esoteric programming language created by David Morgan-Mar.55 Piet programs are abstract geometric images composed of color blocks. The interpreter for Piet operates by moving a "Direction Pointer" (DP) and a "Codel Chooser" (CC) through the image from one color block to an adjacent one. The instruction to be executed is determined by the change in hue and lightness between the two blocks. The value of an integer pushed onto the stack is the size of the color block just exited.5 This elegant design demonstrates that an image can, in fact, serve as a complete and functional program. Piet is a powerful proof-of-concept, showcasing that the spatial arrangement of pixels, rather than a linear sequence of characters, can be a valid and expressive form of program syntax.4.2. Existing Visual Tools and Their LimitationsA comprehensive understanding of the user's request requires distinguishing it from existing visual tools.Block-Based VPLs: Languages like Google's Blockly, MIT's Scratch, and Tynker are highly successful educational tools.1 They use interlocking blocks to hide the complexities of syntax, making programming concepts accessible to novices.1 However, these are fundamentally graphical front-ends that generate conventional, text-based code in languages like Python or JavaScript. The block-based interface is a pedagogical abstraction, but the executable program remains textual.Code Visualization and Debugging Tools: Tools like Python Tutor are invaluable for education and debugging.72 They visualize the step-by-step execution of a program, showing how the stack and heap change over time. Similarly, commercial tools like CodeSee create diagrams of a codebase's architecture, dependencies, and control flow to aid in comprehension and onboarding.25 While these tools use visual means to explain code, they do not treat the visualization itself as the program. The distinction is between a program's visual explanation and its visual essence.These examples highlight a critical issue: the "scaling-up problem" in visual programming languages.67 As a program grows in complexity, the visual representation can become cluttered and overwhelming, making it difficult to read and debug. This is a fundamental challenge for any truly visual language. The solution, in both software engineering and VPL design, is hierarchical abstraction and modularity.77 A practical "Image-as-Code" system would need to be architected with this principle in mind, allowing complex programs to be composed of smaller, reusable image modules. The user could "zoom in" on a single pixel-block to see a sub-program, much like clicking into a function in a text-based debugger.5. Implementation Challenges, Trade-offs, and Recommendations5.1. The Inevitable Performance OverheadA pixel-based interpreter, by its very nature, would face significant performance challenges. Interpreters, in general, are already slower than compiled code, and an interpreter that must read and decode image data pixel by pixel would introduce additional overhead.81 Libraries like Pillow provide methods for pixel-level access (getpixel(), load()), but these are known to be slow for iterating over an entire image.61 The performance would not be competitive with standard Python interpreters, which are already highly optimized. The main value of such a system would lie not in its speed but in its unique approach to computation and its potential as a pedagogical or artistic tool. This is a critical trade-off that must be acknowledged.5.2. The Challenge of "Debugging a Picture"Debugging is a process of understanding a program's state and behavior. For a pixel-based language, this process would take on a new form. While tools like Python Tutor visually represent the state of the stack and heap, debugging an abstract image program would require a novel interface.67 A SyntaxError would not be a line number and a caret but a miscolored or misplaced pixel. A runtime error would manifest as an unexpected change in the visual state of the program. A robust visual debugger would be essential, showing the interpreter's "program counter" moving through the image and dynamically updating a separate, real-time visualization of the stack and variable space.67 This would be a powerful learning tool, but also a complex engineering challenge.5.3. Recommendations for a Proof-of-ConceptFor an individual or team interested in building a proof-of-concept for this system, a strategic, phased approach is recommended:Start with a Small, Manageable Subset of Python: Do not attempt to implement the entire Python language. Instead, select a limited subset of functionality, such as basic arithmetic (+, -, *), variable assignment, and a simple conditional statement (if/else).84 This allows for a focused effort on the core mechanics of the pixel-based system.Leverage Existing, High-Performance Libraries: Avoid building low-level image processing routines from scratch. Python libraries like Pillow for image manipulation and NumPy for efficient, array-based operations are indispensable.61Prioritize the Interpreter's State Visualization: The true value of this project lies in its ability to make the abstract process of computation tangible. Therefore, focus heavily on creating a clear, interactive visualization of the interpreter's state as it runs through the image. This will serve as the most compelling and educational aspect of the project, even if the performance is not the primary goal.6.
